# 二次元搜打撤 + SLG 可行性讨论文档评审

## 总体评价

当前文档已经能清楚表达“为什么二次元搜打撤需要引入 SLG 基建经营”的核心逻辑，也覆盖了资源消耗、风险损失、PVP 收益、赛季重置、联盟荣誉、商业化等关键模块。作为头脑风暴后的阶段性沉淀是合格的。

但如果对标一份正式的游戏设计方案或立项讨论文档，目前仍偏“方向性论证”和“系统想法合集”，还缺少更清晰的产品边界、玩家体验闭环、系统优先级、数值经济验证、竞品对比和风险验证方案。

## 主要问题

### 1. 文档定位还不够明确

当前标题是“可行性讨论最终文档”，但内容同时承担了多个角色：

- 玩法方向说明；
- 商业化原则；
- 系统设计草案；
- 赛季机制讨论；
- 联盟与荣誉设计；
- 风险规避方案。

这会导致读者不容易判断它到底是“立项前方向论证”，还是“玩法系统设计方案”。

建议后续拆成两层：

- **立项论证版**：回答为什么做、做给谁、和竞品差异是什么、风险在哪里；
- **系统设计版**：回答具体怎么玩、系统如何循环、数值如何消耗、赛季如何结算。

### 2. 目标用户画像仍然偏泛

文档多次提到“二次元玩家更偏养成”，这个判断方向没错，但还不够细。

二次元玩家内部差异很大，例如：

- 剧情党；
- 角色厨；
- 收集党；
- 强度党；
- PVP 玩家；
- 轻度休闲玩家；
- SLG 联盟玩家；
- 搜打撤硬核玩家。

目前文档没有明确主目标用户到底是谁。如果目标用户不清晰，后续系统权重会摇摆：到底是偏角色养成，偏撤离战斗，还是偏联盟赛季？

建议补一节“目标用户与非目标用户”。

### 3. 核心体验优先级需要排序

文档现在把很多体验都放进来了：

- 搜打撤；
- 小队养成；
- 基地经营；
- 兵工厂；
- 联盟；
- 赛季；
- PVP；
- 红区；
- 订单；
- 前线建设；
- 分享战报。

问题是这些模块都合理，但正式方案需要明确主次。

建议明确三层优先级：

1. **核心体验**：每个玩家每天都要感受到的内容；
2. **中期驱动**：玩家玩 2-4 周后继续留下来的原因；
3. **赛季目标**：玩家玩完整赛季后的荣誉和追求。

否则系统会显得“大而全”，但产品焦点不够锐利。

### 4. 搜打撤单局体验还不够具体

文档解释了局外 SLG、资源、联盟、赛季，但对“单局怎么玩”描述偏少。

目前还缺少：

- 单局时长；
- 地图规模；
- 玩家人数；
- 小队人数；
- PVE / PVP 比例；
- 撤离点规则；
- 资源点分布；
- Boss / 精英怪出现方式；
- 情报如何影响进局决策；
- 失败后体验链路；
- 成功撤离后的结算节奏。

但搜打撤的核心爽感其实在单局。如果单局体验不成立，局外系统再完整也会变成“养成套壳”。

建议后续补一节“单局体验样例”。

### 5. 经济闭环还缺少验证模型

文档提出了很多消耗口：弹药、药品、耐久、订单、前线建设、武器改造、角色状态等。

但还没有说明：

- 玩家一天平均产出多少资源；
- 一局平均消耗多少资源；
- 高手正收益比例如何控制；
- 资源通胀如何监控；
- 普通玩家是否会被消耗压垮；
- 大佬是否会通过付费绕过消耗；
- 订单消耗和赛季消耗是否会变成纯填坑。

正式设计需要至少有一个“资源流入 / 流出模型”。

建议补：

```text
资源来源 → 资源沉淀 → 资源消耗 → 资源回收 → 赛季折算
```

并按普通玩家、中度玩家、核心玩家、大佬四类分别估算。

### 6. PVP 收益与轻量保护之间仍有张力

第 6 节已经补充了“长期资产保护 + 本局收益可争夺 + 高危赌注”。这个方向是对的。

但仍有一个设计风险：

- 如果掉落太轻，PVP 没爽感；
- 如果掉落太重，二次元玩家不敢进高危区；
- 如果系统额外生成击败奖励太多，可能被刷分；
- 如果高危赌注收益太高，会逼普通玩家也去赌。

建议后续补“反刷机制”和“掉落强度分级表”。

例如：

- 同联盟 / 好友击败不计奖励；
- 短时间重复击败同一玩家收益衰减；
- 低风险区不产出 PVP 铭牌奖励；
- 红区收益高但有入场成本和匹配分层。

### 7. SLG 部分目前更像“基建经营”，传统 SLG 特征不足

文档中 SLG 主要体现在：

- 基地建设；
- 资源消耗；
- 联盟前线；
- 赛季排名。

但传统 SLG 的强特征包括：

- 空间占领；
- 联盟外交；
- 大规模协同；
- 迁城 / 行军 / 驻防；
- 资源点控制；
- 战略调度。

当前方案为了适配二次元和轻量化，弱化了这些内容，这是合理的，但也会导致“SLG 感”不足。

建议文档里改用更准确的表述：

> “SLG 化的基地经营与联盟赛季目标”，而不是完整传统 SLG。

### 8. 联盟玩法缺少冲突强度梯度

文档提出联盟从“掠夺型联盟”转为“战役型联盟”，这是比较好的方向。

但如果联盟之间只是拼贡献、拼订单、拼 Boss，可能会偏弱，缺少对抗张力。

建议增加联盟冲突梯度：

| 层级 | 冲突形式 | 损失强度 |
|---|---|---|
| 低 | 联盟订单排名、贡献榜 | 无损失 |
| 中 | 限时前线资源点竞速 | 机会损失 |
| 高 | 红区战区争夺、运输队拦截 | 本局收益损失 |
| 赛季 | 战区总指挥联盟争夺 | 荣誉差异，无长期资产损失 |

这样联盟有竞争，但不走传统 SLG 的毁灭式掠夺。

### 9. 赛季切换逻辑还可以更清晰

文档已经提出软重置，但还可以进一步拆成：

- 什么是永久资产；
- 什么是赛季资产；
- 什么是可折算资产；
- 什么是过期资产；
- 赛季结束时如何结算；
- 新赛季如何给玩家新目标。

建议加一张“赛季资产处理表”，否则玩家预期不够清楚。

### 10. 商业化章节偏原则，缺少约束边界

当前商业化章节列出了适合、谨慎、不建议付费内容，方向是对的。

但正式方案里还需要明确：

- 付费是否能影响 PVP 数值；
- 付费加速是否有每日上限；
- 付费资源是否能进入交易；
- 付费装备是否可掉落；
- 外观是否有属性；
- 大佬是否能通过付费绕过赛季门槛。

否则商业化一旦失控，会直接破坏整个轻量搜打撤生态。

## 次要问题

### 1. 内容存在一定重复

“轻量搜打撤”“不死亡全掉”“不打爆基地”“长期资产保护”“赛季软重置”等观点在多个章节重复出现。作为头脑风暴文档可以接受，但正式方案建议压缩。

### 2. 缺少竞品对比表

文档提到了《逃离塔科夫》《三角洲行动》《万国觉醒》，但没有形成对比表。

建议补：

| 产品 | 核心循环 | 死亡损失 | 赛季处理 | 联盟强度 | 本方案借鉴点 | 本方案规避点 |

### 3. 缺少 MVP 版本

当前方案比较完整，但如果要验证，应先定义 MVP：

- 先做哪些系统；
- 哪些暂缓；
- 第一版验证什么；
- 成功指标是什么。

建议 MVP 不要上来就做完整联盟赛季，而是先验证：

```text
小队撤离 → 物资带回 → 兵工厂生产 → 装备再投入 → 风险收益是否成立
```

### 4. 缺少关键指标

建议补一些验证指标：

- 单局撤离成功率；
- 平均单局净收益；
- 资源库存增长率；
- 装备消耗率；
- PVP 参与率；
- 安全箱使用率；
- 订单完成率；
- 次日 / 七日留存；
- 赛季末参与率；
- 战报分享率。

## 建议的文档结构调整

如果要改成更正式的设计方案，建议结构如下：

1. **方案摘要**
2. **目标用户与设计目标**
3. **核心问题：为什么搜打撤需要 SLG 化承接**
4. **竞品对比：塔科夫 / 三角洲 / 万国觉醒 / 本方案**
5. **核心循环：局内撤离 + 局外基地 + 赛季联盟**
6. **单局玩法样例**
7. **局外基建与兵工厂系统**
8. **资源经济：流入、流出、膨胀控制**
9. **风险与掉落：PVP 收益和长期资产保护**
10. **战区分层与匹配规则**
11. **联盟与赛季荣誉**
12. **商业化边界**
13. **MVP 验证版本**
14. **主要风险与验证指标**

## 总结

当前文档的优点是方向清晰，已经抓住了二次元搜打撤与传统硬核搜打撤、传统 SLG 的核心差异：不靠死亡全掉和基地被打爆制造活跃，而靠局内风险决策、局外养成消耗、联盟赛季目标和荣誉分享形成持续循环。

主要不足是还偏概念论证，缺少正式设计方案中需要的“目标用户、单局样例、经济模型、MVP 范围、竞品对比、验证指标和风险闭环”。

如果下一步继续推进，建议优先补三块：

1. **目标用户与 MVP 玩法闭环**；
2. **资源经济流入 / 流出模型**；
3. **单局搜打撤样例与战区分层规则**。
