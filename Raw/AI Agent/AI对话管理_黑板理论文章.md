# AI 的对话管理：把 Context Window 当作一块有限黑板

在使用大模型时，我们常常会把它想象成一个“什么都记得”的智能助手。但从工程角度看，大模型并不真正拥有无限记忆。它每次回答问题时，依赖的是被放进 `Context Window` 里的内容：系统提示词、用户输入、历史对话、工具结果、知识库片段等。这个窗口就像一块面积有限的黑板，模型只能看到黑板上当前写着什么；一旦内容太多，早期信息就可能被擦掉、压缩，甚至完全丢失。

这张图想表达的核心，就是 AI 对话管理中的“黑板理论”。所谓黑板，并不是单纯的聊天记录，而是模型当前可见的全部上下文空间。左侧提到的大模型 `Context Window`，可以理解为一块有限面积的黑板；右侧则把进入黑板的内容拆成几类：`Instructions`、`Knowledge`、`Tools`。这些内容会共同进入模型的上下文窗口，影响模型最终的回答。

## 一、为什么 Context Window 是有限黑板

大模型不是在每次对话中自动拥有全部历史记忆，而是依赖当前上下文进行推理。上下文越长，模型能参考的信息越多，但窗口大小始终有限。随着对话推进，新的消息、工具调用结果、文件内容、知识库检索结果会不断写入黑板。如果缺少管理，最早写入的关键信息可能会被后续内容挤出窗口。

这就会带来一个典型问题：用户在对话早期提出过重要约束，模型一开始遵守得很好，但经过很多轮之后开始忘记。例如项目规范、角色设定、业务目标、命名约定、设计边界等，如果没有被重新整理和保留，就可能在上下文膨胀后丢失。

因此，AI 对话管理的本质，不是简单地“保留所有历史”，而是决定：哪些内容应该继续留在黑板上，哪些内容可以擦掉，哪些内容应该压缩成摘要，哪些内容需要固化为更稳定的知识。

## 二、黑板上通常写着什么

从图中可以看到，进入大模型上下文的内容大致可以分成三类。

第一类是 `Instructions`，也就是指令。它包括系统提示词、角色设定、任务目标、输出格式要求、开发规范等。这部分通常决定模型“应该怎么做”。例如要求模型用中文回答、遵守某种代码风格、不要泄露隐私、按照某个流程完成任务等，都属于指令层。

第二类是 `Knowledge`，也就是知识。它包括用户提供的背景、项目文档、业务资料、知识库检索结果、历史总结等。这部分决定模型“知道什么”。如果知识不完整，模型就可能凭空猜测；如果知识过期，模型就可能给出错误建议。

第三类是 `Tools`，也就是工具信息。工具调用结果、文件读取内容、搜索结果、日志、报错信息等，都会进入上下文。这些内容通常非常具体，也非常占空间。工具结果能让模型获得真实环境信息，但如果不加筛选，也会快速占满黑板。

## 三、对话为什么需要管理

如果把所有内容都无差别写进黑板，短期看似信息充足，长期反而会降低质量。因为黑板面积有限，内容越多，越需要选择。真正有效的对话管理，是让模型在需要时看到最关键的信息，而不是看到最多的信息。

例如，在一个长期项目中，早期讨论过的总体目标、架构决策、关键约束，应该被压缩成稳定摘要；临时调试日志、一次性搜索结果、已经解决的问题，则可以在任务完成后移出当前上下文。否则模型会被大量低价值信息干扰，甚至出现重点漂移。

这也是图中提到 `Context Management` 的意义。它类似“记忆剪枝”：定期压缩历史记录，删除噪声，保留关键结论。不是把过去全删掉，而是把过去整理成更适合继续使用的形态。

## 四、System Prompt 像黑板顶部的固定规则

图中还提到 `System Prompt`，可以理解为黑板最上方的固定区域。它通常不随普通对话轻易改变，用来锁定模型的基本行为和角色边界。

例如，如果我们希望模型始终像一个资深游戏系统策划一样思考，就可以在系统提示词中规定它的角色、关注点、输出方式。如果希望模型在代码任务中遵守某些工程规范，也可以把这些规范放在更高优先级的位置。

但系统提示词也不能无限膨胀。如果把所有规则都塞进系统提示词，反而会造成规则冲突和注意力稀释。更好的做法是：系统提示词只放长期稳定、必须遵守的原则；具体任务资料、项目背景和临时上下文，则通过知识库、文件、摘要或工具动态补充。

## 五、好的对话管理应该怎么做

一个成熟的 AI 对话系统，应该具备几种能力。

首先是摘要能力。长对话进行到一定阶段，需要把已经确认的结论压缩成简明摘要。例如“我们已经确定玩法定位是轻量搜打撤 + SLG 基建 + 二次元小队养成”，这类结论比完整聊天记录更适合长期保留。

其次是分层能力。不是所有信息都应该处在同一层级。系统规则、用户偏好、项目长期目标、当前任务上下文、临时工具结果，应该分层管理。越稳定、越重要的信息，越应该放在更可靠的位置。

第三是检索能力。不是所有知识都要常驻黑板。大量文档可以放在外部知识库，需要时再检索相关片段放入上下文。这样既节省窗口，又能保持知识完整。

第四是遗忘能力。遗忘不是缺陷，而是一种必要机制。已经无用的日志、重复内容、错误方向、过期假设，都应该被移出黑板。否则上下文会越来越脏，模型的判断也会越来越不稳定。

## 六、对 AI Agent 的启发

对于 AI Agent 来说，对话管理决定了它能否完成长期任务。短任务只需要临时上下文，但长期任务需要持续记忆、阶段总结和目标保持。否则 Agent 很容易在多轮执行后忘记最初目标，或者被中间细节牵着走。

好的 Agent 不只是会调用工具，还要会管理自己的黑板：什么时候读文件，什么时候摘要，什么时候丢弃临时结果，什么时候把结论写入长期记忆，什么时候重新检索知识库。它的能力不只来自模型本身，也来自上下文组织方式。

换句话说，AI 的智能并不只取决于“大脑”有多强，也取决于“桌面”有多整洁。Context Window 就是模型工作时的桌面；桌面上放什么、怎么放、什么时候清理，都会直接影响最终表现。

## 七、总结

这张图的核心观点可以概括为一句话：

> 大模型的上下文窗口是一块有限黑板，AI 对话管理的关键，就是持续决定哪些信息写上去、哪些信息擦掉、哪些信息压缩保存。

`Instructions` 决定模型如何行动，`Knowledge` 决定模型知道什么，`Tools` 提供真实环境反馈。而 `Context Management` 则负责在有限空间里维持信息质量，避免关键信息被噪声淹没。

因此，真正高质量的 AI 应用，不只是把更多内容塞给模型，而是让模型在正确的时间看到正确的信息。
