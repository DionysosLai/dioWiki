# MCP

## 定义

**MCP（Model Context Protocol）** 是面向大模型的工具接口标准：把可用工具以结构化方式（名称、描述、入参 schema 等）暴露给模型，由宿主（如 Claude Code、Codex）把工具列表注入上下文，供模型选择并调用。

## 要点

### 成本：工具元信息吃 Token

每次请求往往附带**全部可用工具**的详细说明，而不只是工具名。[[mcp-vs-cli]] 以 GitHub MCP Server 为例：44 个工具合计约 1683 行 / ~14268 tokens；多 Server 叠加时，仅「工具说明书」就可能成为显著费用。这与 [[上下文管理]] 中「黑板面积有限」直接相关——Tools 层说明过重会挤占 Instructions / Knowledge。

### 优势：可控与安全

- **可控**：参数走 JSON 字段与转义规则，文件名含引号/空格等不易破坏调用结构；相对 shell 拼接更不易隐蔽出错。
- **安全**：能力面由工具设计者限定，「只能做被允许的事」。共享云端 / 企业环境往往允许 MCP，却不愿开放任意 `bash`。

### 劣势：调度链路与灵活度

多步任务常变成「模型思考 → 调工具 → 结果回模型 → 再思考」的串行往返，模型是调度中心，延迟与 Token 都叠在轮次上。把多步焊成单一「超级 MCP 工具」可缩短轮次，但需求一变就要重开发；组合灵活度不如 [[CLI作为Agent工具接口]]。

## 适用场景（来自 [[mcp-vs-cli]]）

更适合对**稳定性、权限边界、多租户安全**要求高的场景（企业、云端自动化）。个人轻量 Agent 中占比可能下降，但不会消失。
