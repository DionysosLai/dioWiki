# AI 的对话管理：把 Context Window 当作一块有限黑板

| 属性 | 值 |

## 核心摘要

文章将大模型的 `Context Window` 类比为一块面积有限的黑板：模型每次回答时只能看到当前被写入上下文窗口的内容，包括系统指令、用户输入、历史对话、知识库片段、工具调用结果等。随着对话推进，如果缺少管理，早期的重要约束和结论会被后续信息挤出窗口，导致模型遗忘目标、丢失边界或被噪声干扰。

文章的核心观点是：AI 对话管理不是简单保留全部历史，而是持续决定哪些信息应该写入黑板、哪些内容可以擦除、哪些结论需要压缩成摘要、哪些知识需要固化到长期记忆或 Wiki 中。

## 关键观点

1. **Context Window 是有限黑板**：模型依赖当前上下文推理，而不是自动拥有全部历史记忆。
2. **上下文内容需要分层**：`Instructions` 决定模型如何行动，`Knowledge` 决定模型知道什么，`Tools` 提供真实环境反馈。
3. **长对话需要摘要和剪枝**：项目目标、架构决策、关键约束应压缩保留，临时日志和一次性工具结果应及时移出当前上下文。
4. **System Prompt 是固定规则区**：适合放长期稳定、必须遵守的行为原则，但不应无限膨胀。
5. **Agent 能力取决于上下文组织**：好的 Agent 不只是会调用工具，还要会决定何时读文件、何时摘要、何时遗忘、何时写入长期知识。

## 结构梳理

### 1. 黑板理论

文章用黑板比喻大模型上下文窗口：黑板面积有限，写入内容越多，越需要选择和组织。对话越长，越容易出现早期关键信息被挤出的问题。

### 2. 上下文三类内容

| 类型 | 作用 | 示例 |
|------|------|------|
| Instructions | 决定模型应该怎么做 | 系统提示词、角色设定、输出格式、开发规范 |
| Knowledge | 决定模型知道什么 | 项目背景、业务资料、知识库片段、历史总结 |
| Tools | 提供真实环境反馈 | 文件读取、搜索结果、日志、报错、工具执行结果 |

### 3. 对话管理方法

文章提出成熟的对话管理应具备四种能力：

- **摘要能力**：把长对话中的关键结论压缩为稳定摘要。
- **分层能力**：区分系统规则、用户偏好、项目目标、当前任务和临时工具结果。
- **检索能力**：大量知识不常驻上下文，而是在需要时从知识库检索。
- **遗忘能力**：移除无用日志、重复内容、过期假设和错误方向，避免上下文污染。

## 可复用方法论

| 方法 | 说明 | 可迁移场景 |
|------|------|------------|
| 有限黑板模型 | 把上下文窗口视为有限工作区，避免无限堆信息 | AI Agent 设计、长对话管理 |
| 信息分层 | 将指令、知识、工具结果分层管理 | 系统 Prompt 设计、知识库接入 |
| 阶段摘要 | 定期把长对话压缩为关键结论 | 长期项目协作、方案讨论 |
| 上下文剪枝 | 删除噪声和过期内容，保留高价值信息 | 调试、代码任务、研究任务 |
| 外部知识库检索 | 不让全部知识常驻上下文，需要时动态取用 | Wiki、RAG、个人知识管理 |
